# microbiome-design：课题可行性与研究设计

## 快速调用示例

```
/microbiome-design 宏基因组 IBD患者60例+60对照 横断面 论文发表
/microbiome-design 16S 2型糖尿病干预前后各40例 纵向 基金申请
/microbiome-design 多组学(宏基因组+代谢组) 肝硬化队列30例×3时间点 纵向 可行性评估
/microbiome-design 16S 新生儿队列200例追踪至1岁 纵向 论文发表
```

## 职责

帮助研究者判断手头数据能做什么深度的研究，设计严谨的研究方案，避免后期审稿时被混杂因素和方法学问题卡死。

**执行顺序**：收到用户描述后，先查本地 RAG 知识库找同类研究设计参考，再结合内置评估框架给出建议。

## 步骤 1 — 本地知识库检索（优先）

查找与用户疾病/方法最相关的已精读文献，作为设计参考依据：

```bash
# 按疾病话题查找同类研究
cat knowledge/concepts/topics/{disease_topic}.md 2>/dev/null | head -60
# 按关键词搜索已精读条目
grep -l "{disease}" knowledge/concepts/entries/*.md 2>/dev/null | head -5
# 同时检查是否有同类方法的可执行节点（可直接获取运行代码）
ls knowledge/papers/pmid_*.json 2>/dev/null | xargs -I{} basename {} .json | sed 's/pmid_//'
```

检索结果的使用规则：
- **概念节点**（`knowledge/concepts/entries/`）：引用其设计方案、样本量、验证策略作为设计依据
- **可执行节点**（`knowledge/papers/`）：若有同类分析方法，在回答末尾**主动提示用户调用 `/microbiome-article-analysis <PMID>`** 获取可直接运行的代码，避免用户从零写代码

## 步骤 2 — 数据充分性评估

### 样本量：效应量驱动，而非固定阈值

**第一步：先查同类研究的报道效应量**

在给出样本量建议之前，用 `WebSearch` 查找该疾病+该测序类型的同类文献报道的效应量，例如：
```
"{disease} gut microbiome {sequencing_type} effect size Cohen's d R-squared PERMANOVA 2023 2024 2025"
```

依据查到的效应量范围，再对照以下参考表：

| 研究终点 | 小效应量（d=0.2） | 中效应量（d=0.5） | 大效应量（d=0.8） |
|---------|--------------|--------------|--------------|
| 菌群多样性差异（Wilcoxon，α=0.05，β=0.8） | ≥ 200/组 | ≥ 35/组 | ≥ 15/组 |
| 差异物种分析（FDR校正后） | ≥ 50/组 | ≥ 20/组 | ≥ 10/组 |
| 机器学习诊断（AUC 0.85，95%CI宽度<0.1） | ≥ 150/组 | ≥ 80/组 | ≥ 50/组 |
| 纵向干预（自身对照，配对检验） | ≥ 50例 | ≥ 25例 | ≥ 15例 |

若需精确计算，推荐使用 [mPower](https://link.springer.com/article/10.1186/s40168-026-02427-4)（基于真实数据的半参数模拟）或 [micropower](https://github.com/brendankelly/micropower)（PERMANOVA 专用），在结论中说明工具名称和输入参数，不在技能内执行模拟。

### 测序深度参考
- 16S：≥ 20,000 reads/样本（V3-V4 区，Illumina PE250）
- 宏基因组：≥ 5G/样本（物种级）；≥ 10G/样本（菌株级/功能分析）
- 多组学：宏基因组 + 代谢组搭配时，代谢组需同批次采集

### 测序策略选择
- **16S**：适合大队列物种描述，成本低；不适合功能分析和菌株分辨
- **宏基因组**：适合功能通路、菌株追踪、MAGs 组装；成本高
- **多组学**：适合机制探索；需要严格样本采集同步

## 步骤 3 — 研究设计类型与时间点规划

### 设计类型对应的因果推断强度

| 设计类型 | 因果推断强度 | 最适合的研究目标 |
|---------|------------|--------------|
| 横断面 | 关联性（最弱） | 生物标志物发现、疾病特征描述 |
| 配对病例对照 | 关联性（控制了个体差异） | 精准差异分析、样本量受限时 |
| 纵向观察 | 时序关联 | 动态变化描述、预测模型 |
| 纵向干预（前后对照） | 干预效应（中等） | 治疗/饮食干预效果评估 |
| RCT | 因果效应（强） | 益生菌/FMT 临床验证 |

### 纵向设计时间点间隔建议

| 疾病/场景 | 建议采样间隔 | 最少时间点数 | 依据 |
|---------|------------|-----------|------|
| 抗生素干预后恢复 | 0/7天/1月/3月 | 4 | 抗生素后菌群恢复周期约 3 个月 |
| 益生菌干预 | 0/4周/8周/停药后4周 | 4 | 益生菌定植效应窗口期 |
| IBD 疾病活动度追踪 | 每 3 个月 × 1 年 | 5 | 复发缓解周期 |
| 体重/代谢干预 | 0/3月/6月/12月 | 4 | 代谢改善的菌群响应周期 |
| 新生儿发育队列 | 出生/1月/3月/6月/12月 | 5 | 菌群定植关键窗口期 |
| 化疗/免疫治疗 | 每疗程前后 + 随访 | ≥ 4 | 治疗对菌群扰动的动态窗口 |

## 步骤 4 — 混杂因素核查

**核心混杂因素**（必须记录并在统计模型中控制）：

| 混杂因素 | 收集方式 | 为何重要 |
|---------|---------|---------|
| 年龄 | 连续变量（岁） | 菌群组成随年龄显著变化 |
| 性别 | M/F | 激素水平影响菌群 |
| BMI | 连续（kg/m²） | 肥胖本身改变菌群，是混杂而非结果 |
| 抗生素使用 | 近1月/3月/6月内 | 强烈扰动菌群，近期使用应排除 |
| 饮食 | 3天饮食日记或FFQ | 饮食是菌群组成最强的决定因素 |
| 采样时间一致性 | 采样时间/运输时间 | >15分钟未冷冻显著影响菌群 |
| 地理位置 | 省/市级别 | 跨中心研究须作为协变量 |

**疾病特异性混杂**（按用户疾病补充说明）：
- IBD：用药类型（氨基水杨酸/免疫抑制剂/生物制剂）、手术史、疾病活动度
- 肿瘤：化疗方案、放疗史、手术时间
- 代谢病：糖化血红蛋白、血脂、用药（二甲双胍已知影响菌群）
- 肝病：Child-Pugh 评分、腹水情况、质子泵抑制剂使用

## 步骤 5 — 因果推断层级判断

这是菌群研究设计最容易出错、也最常被审稿人质疑的部分。**在确定哪些变量需要控制之前，必须先判断每个变量的角色。**

### 三类变量的本质区别

| 变量角色 | 定义 | 处理方式 | 菌群研究典型例子 |
|---------|------|---------|--------------|
| **混杂变量（Confounder）** | 同时影响暴露（菌群）和结局（疾病）的变量 | **必须控制**（纳入统计模型） | 年龄、BMI、抗生素使用 |
| **中介变量（Mediator）** | 位于暴露和结局的因果路径上（菌群→中介→疾病） | **不应控制**（控制会阻断你要研究的路径） | 短链脂肪酸、胆汁酸（若研究菌群如何影响代谢） |
| **对撞变量（Collider）** | 同时被暴露和结局影响的变量 | **绝不控制**（控制会人为制造虚假关联） | 住院状态（若同时被疾病严重程度和菌群失调影响） |

### 常见的因果推断错误场景

**场景 1：把中介变量当混杂控制**
研究「IBD 菌群 → 短链脂肪酸 → 肠道炎症」，若在模型里同时控制短链脂肪酸，则阻断了你要研究的路径，结论无效。

**场景 2：控制对撞引入选择偏倚**
研究「饮食习惯 → 菌群多样性」，若只纳入住院患者（同时受饮食和疾病影响），会在饮食和疾病间制造虚假关联。

**场景 3：忽略反向因果**
横断面研究无法区分「菌群失调导致 IBD」还是「IBD 导致菌群失调」——这不是混杂问题，是设计本身的根本局限，需要在 Discussion 明确说明，或通过纵向/MR 设计解决。

### 变量角色判断清单

收到用户描述后，对用户提到的关键变量逐一判断：

1. 这个变量是在暴露（菌群变化）之前还是之后发生的？
   - 之前 → 可能是混杂，考虑控制
   - 之后 → 可能是中介或结局，**不应控制**

2. 这个变量是否位于菌群→疾病的因果路径上？
   - 是 → 中介变量，研究机制时才分析，**不应纳入主模型**
   - 否 → 混杂变量，应控制

3. 这个变量是否同时受菌群和疾病的影响？
   - 是 → 对撞变量，**绝对不能控制**

### 工具推荐（决策层，不执行）
- `ggdag`（R 包）：绘制有向无环图（DAG），可视化变量因果结构，自动识别最小充分调整集
- DAG 绘制参考：[dagitty.net](http://www.dagitty.net/)（在线工具）

**行动建议**：在确定最终分析方案前，建议用 dagitty.net 草绘变量因果结构图，明确最小充分调整集（minimal sufficient adjustment set）。在回答的「混杂控制方案」部分，说明基于 DAG 判断结果给出的调整变量列表，以及哪些变量被排除及原因。

## 步骤 6 — 报告规范预检

根据设计类型，提前说明对应的报告规范关键要求，避免写作时信息缺失：

| 设计类型 | 对应规范 | 菌群研究最易遗漏的条目 |
|---------|---------|-------------------|
| 横断面观察研究 | **STROBE** | 暴露测量方法（DNA提取/测序平台）、混杂因素完整列表、样本量计算依据 |
| 纵向队列研究 | **STROBE** | 随访率、失访原因、时间点选择依据 |
| 干预研究（非随机） | **TREND** | 组间基线可比性、干预方案标准化说明 |
| RCT | **CONSORT 2025** | 随机化方案、分配隐藏、盲法实施、CONSORT 流程图 |
| 诊断准确性研究 | **STARD** | 金标准定义、spectrum bias 说明、盲法评估 |

**STORMS 规范**（菌群研究专用）：所有菌群研究额外需要报告 DNA 提取方法、引物序列、测序平台型号、生信流程版本，无论何种设计类型。

## 回答框架

完成步骤 1-6 的内部评估后，按以下结构向用户输出结果。每个板块的判断依据必须来自前述步骤的检索或分析，不得凭空生成。

### 1. 研究定位

一句话明确：**这个研究在当前领域的位置是什么**——能填补什么空白，与最近同类研究（来自步骤 1 RAG 检索）的核心差异是什么。

### 2. 可行性判断
直接给出：**可以做 / 有限制（说明限制）/ 不建议（说明原因）**

用本地 RAG 检索结果或 WebSearch 找到的同类研究作为判断依据，不凭空给出结论。同时说明用户样本量在该疾病领域已知效应量下对应的统计功效评估。

### 3. 最小可行路径
当前数据条件下，最简单、最能发表的研究方案是什么。明确说明：
- 分析类型
- 预期能投的期刊级别
- 最关键的统计方法

### 4. 升级路径

| 追加内容 | 分析能力提升 | 期刊档次提升 |
|---------|------------|------------|
| 独立验证队列（同疾病，不同中心） | 外部效度 ↑↑ | +1-2档 |
| 纵向随访样本（≥ 3 时间点） | 动态建模、因果推断 ↑ | +1档 |
| 代谢组/转录组补充 | 机制说明能力 ↑↑ | +1-2档 |
| 动物模型（FMT/无菌鼠验证） | 因果推断 ↑↑↑ | +2-3档 |
| 多中心扩大样本（> 500例） | 统计效能 ↑，泛化性 ↑↑ | 顶刊可能 |

### 5. 混杂控制方案
具体说明哪些混杂因素需要在统计模型中控制（MaAsLin2/adonis2 的协变量列表），说明基于步骤 5 DAG 判断排除的中介/对撞变量，以及缺失哪些变量会被审稿人质疑。

### 6. 风险提示
列出 2-3 个最可能被审稿人质疑的方法学问题，配合应对策略。重点标注步骤 5 中识别出的因果推断风险（错误控制中介/对撞是最常见的隐性硬伤）。

### 7. 工作计划框架（仅研究目标为「基金申请」时输出）

给出研究周期的时间线估算，按月份分解关键节点：

| 阶段 | 时间估算 | 关键产出 |
|------|---------|---------|
| 伦理审批 + 样本采集 | 月1-月N | 知情同意书、元数据规范化 |
| 测序 + 质控 | 月N+1 ~ N+2 | 合格样本数据集 |
| 核心分析 | 月N+2 ~ N+4 | 差异分析/建模结果 |
| 验证与机制 | 月N+4 ~ N+8 | 独立队列验证/动物实验（若有）|
| 写作投稿 | 月N+8 ~ N+12 | 论文初稿、投稿 |

具体月份根据用户描述的样本量和设计复杂度调整，输出后提示衔接 `/microbiome-grant` 完成技术路线写作。
